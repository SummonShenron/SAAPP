## HIGH: #193 — a waiting card can no longer be ended, and it blocks the conversation

**What happens.** Before #193, closing the tab or reloading cancelled the turn, so any wait inside it (a calendar/doc change card, a choice card, an edit's Apply/Decline, a runner check) ended at once. Those waits (`change_cards.py`, `choice_cards.py`, `local_edit_decisions.py`, `runner_jobs.py`) only react to `asyncio.CancelledError`; the docstrings say "a turn that is cancelled (Stop, or the person left) stops waiting". After #193 a dropped connection no longer cancels the turn, and Stop is a flag (`steering.request_stop`) that `app.py` checks in exactly two loops (between graph events, and in the token stream). A turn that is blocked inside a wait never reaches either loop.

**Effect.** The person closes the page (or reloads) while a card is waiting. The card is not saved, so it cannot be pressed from the reloaded page. The turn waits the full wait (600 s by default). Meanwhile `/api/chat` answers 409 "Sonic is still finishing the last reply", and the page's catch-up polls for up to 10 minutes. Pressing Stop returns `"stopping"` and changes nothing.

**Reproduced** (scratch script, real `detached_stream`, `steering` and `change_cards`; browser leaves at 0.4 s, Stop at 0.4 s):

```
 0.4s browser gone   -> turn still running: True   still waiting on a press: True
 0.4s Stop pressed   -> server says: 'stopping'
 0.8s after Stop     -> turn still running: True   still waiting on a press: True
 4.1s the turn finally ended on its own wait timeout (the real wait is 600 s)
```

**Suggested fix.** Give each turn an interrupt that the waits also listen to: set by `request_stop`, and set when the reader leaves while the turn is waiting for a person. Each wait already ticks every 20 s; make it `asyncio.wait` on the answer event and the interrupt, and end as "no decision". Add tests for "waiting + browser leaves" and "waiting + Stop" for each of the four waits. None of the PR's detached-turn tests touch a wait.

## MEDIUM

**#193, the 409 burns a guest's counted turn.** The guest allowance is counted before the 409 is raised, so a refused request still costs one of the visitor's daily turns. Check for a running turn before counting.

**#193, nothing bounds detached turns.** A turn now runs to the end whether or not anyone reads it. Per conversation it is limited by the 409, per person by the budgets, but there is no process-wide ceiling or maximum lifetime. Consider a cap on concurrent detached turns and a maximum age.

**#188, a new kind of personal data is not disclosed.** `user_recurring_struggles` stores, per person, the names of saved people and the start time of each "upset episode". Clear All erases it (tested) and it expires after 90 days, but: it is not on the Privacy page or in `docs/consent-audit.md` (the list of collections that carry a person's identifier), `test_privacy_disclosure.py` does not watch collections, the Memory page does not show it, and deleting a saved person does not remove their name from it. Add the disclosure and a per-person forget before anything reads it.

**#188, names that are ordinary words.** `person_of_turn` matches `\b<name>\b` ignoring case. The stop list (`conversation_people._NOT_NAMES`) has 42 entries and does not include Will, May, Mark, Grace, Hope, Bill, Dawn, Rich, Frank, Pat, Skip and similar, so "this will never work" counts as upset about a saved person called Will. Harmless while it only counts; the planned step-back question would say something false and unsettling. Use a case-sensitive, capitalised match for ambiguous names.

**#188, "frustrated" is treated as being upset about a person.** A coworker or a code reviewer would count. Before step 2, use the relationship type from the saved facts, and keep step-back questions out of safety turns.

## LOW

**#187**
- The 1-hour cache lifetime is a bet on turn cadence. A 1-hour write costs 2x input versus 1.25x for 5 minutes, so it pays when the same person has another Claude tool turn within the hour and costs about 0.75x of ~10K tokens more when not (about $0.015 on Sonnet, negligible on Haiku). Watch the first-call cache read share on real turns; `CLAUDE_PREFIX_TTL=5m` reverts it.
- `langchain-anthropic` is not pinned in `requirements.txt`. The 1-hour write count comes from `ephemeral_1h_input_tokens`, which the installed 1.7.6 provides; an older resolve on Render would price 1-hour writes as 5-minute writes (the meter under-counts). Pin `>=1.7`.
- `continue_working` is now always offered and returns before the repeat check, so a model that keeps calling it outside a checkpoint spends steps without being stopped. Cap it.
- The own-material gate is true as described (changelog line is 236 characters). The counter `own_material_opened` exists but the reply stamp does not record it, so the Feedback page cannot show thumbs on those turns. Add the tier to the stamp.

**#188**
- `float(os.getenv("STRUGGLE_UPSET_MIN", "0.3"))` and the int ones at import: a blank or malformed value on Render stops the whole app from starting. Use the safe-number pattern used elsewhere.
- A thread hop is spawned every turn although most are not upset; call `upset_this_turn` (pure) before spawning.
- Read-then-write on the document can lose an episode when two turns overlap. Fine for counting; revisit before step 2 depends on it.

**#192**
- `IMPORTED IN:` in the `trace_symbol` result has no cap (uses and definitions do). A widely imported name could add thousands of characters to the model's context on every call.
- Every `trace_symbol` call re-reads every code file, and every proposal runs the cross-file check over up to 30 MB. Acceptable; a per-turn read cache or a timing counter would show whether it matters.
- A refusal is repeated whenever the problem list differs from the last one, so refusals per turn are bounded only by the step budget. Cap them (for example 3).
- The call-signature check ignores decorators, which can change what a call accepts. Skip decorated functions except the known-safe ones.

**#193**
- A failure inside the detached turn is logged and the stream just ends; the page sees a normal ending with no error event. Put an error event on the queue before the end marker.
- Running and stop state are per process. A deploy or restart mid-turn ends the turn and the page's catch-up then reloads a conversation without the reply. Already noted in the docstring.
