The step budget

Reading spends steps. Doing earns them back.

Every turn gets a small budget. That’s how it stays fast, cheap and unable to run away.

1

Start small

7 steps a turn, 14 in Deep mode, never more than 12 at once. A change request gets at least 6.
2

Don’t read forever

On longer budgets, at ⅓ and ⅔ it must choose: answer now, or name what it still needs. At 2 steps left it asks for everything at once.
3

Acting earns steps back

An edit that was applied, or a check that ran, hands back +4. The same result again earns +2, +1, then nothing. A new failing test is a counter-hit: room to read what the fix needs.
4

The chain ends when it stops landing

A step with no real action earns nothing. A hard cap of 30 steps handed back per turn.

Why you can trust it

Autonomy with brakes.

The more an assistant can do, the less it should be able to do on its own.

1

Propose, then click

Edits show a diff and an Apply button. Commands show the exact line and a Run button. Merges and commits are cards. Nothing changes silently.
2

Two checks, same rules

A command is checked on the server and again on your machine, against the same rules file. Your machine decides last. Tests and servers are asked for by name, never by command.
3

Outside text is data

After it reads a web page, an email, a log or a command’s output, commits are refused that turn. Hidden instructions can’t become actions.
4

A browser that can’t phone out

It looks at pages on your own computer only. Every request to anywhere else is blocked, and a test proves it with a real network address.
5

Spend brakes

Hard daily caps per person and overall, a low-power mode, and cheap models for the loop. A test run can’t spend real money either.
Every rule here came from a real failure.
