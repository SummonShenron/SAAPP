# Public launch readiness

Written 2026-11-05. An honest list, from what the notes and today's work show, of what to fix before opening Sonic to anyone. It is not a verdict on production: nobody has read the production metrics for this list, and "public" here means anyone can sign up. A small invited beta (about 10 to 30 people, coding features limited) needs far less. Items marked UNVERIFIED are things not looked at, not things known to be fine.

## Fix before anyone outside the project uses it
1. **The Apply bug in production.** Twice, on 2026-11-04, the turn ended the moment Apply was pressed (the follow-up text never came). Not reproduced locally (the cause was NOT the card-position commit; locally a backend reload on a Python edit does the same, which is a different cause). Suspect: the wait for Apply lives in one process's memory (`backend/services/local_edit_decisions.py`), so a second worker or instance, or a stream cut by a proxy, loses it. Check Render's start command and instance count; the page's "The server stopped waiting for this answer" notice tells which. UNVERIFIED.
2. **A consent audit of every place a person's code or text leaves for a provider.** On 2026-11-05 the diff reviewer was found sending diffs to Anthropic for people who had not chosen a Claude model (fixed in the working tree; the older version may already be deployed). No test caught it. Do a systematic pass: the reviewer, the conversation-summary and memory models, any env-selected Claude model, the Maps tools, the runner. For each: who chose it, what is sent, is it in the privacy page.
3. **State that lives in one process.** Waiting proposals, applied-change notes, browser sessions and in-flight turns are in memory. Decide and write down: one worker only (`WEB_CONCURRENCY=1`, never scale out without moving this state), or move it to the database.
4. **A test run on every push (CI).** Offered 2026-10-26 and deferred. The fast suite is about 8,200 tests and takes about 16 minutes locally, so the workflow should run a fast subset on push and everything before a release.
5. **A load test.** Designed (`docs/load-test-plan.md`), not built. Without it nobody knows what happens at 30 people at once, and the first real load would be the test.
6. **A cost plan for traffic.** The caps are $5 a day overall and $1 a day per person. A handful of curious people can use the day. Decide what a person sees when the day is gone, and have the paid-tier warning copy ready (`docs/paid-tier-plan.md`, step 1).
7. **The safety copy.** The support ladder, listening mode and crisis handling are built and tested, but the notes say the copy is not clinician-reviewed. Either have it reviewed or say so plainly to the people who use it.
8. **The runner.** It runs commands on other people's machines after they approve each one. Its command language refuses most dangerous things, but nobody outside the project has reviewed it. For a beta, keep it to people who opt in; before public, get a second reader to threat-model it.
9. **Terms, privacy and data rights.** The privacy page exists and names the providers. UNVERIFIED: terms of service, how a person deletes or exports their data, and whether each page says what is true after the model presets and the paid tier.

## Progress on the fix-first list (2026-11-05, uncommitted)
- **Item 1, Apply bug: made diagnosable, not fixed.** The cause is still unknown. When an Apply or Decline finds no turn waiting, the server now says why (`cancelled` = the stream was cut while the turn waited; `timeout`; `decided` = a second press; `not_here` = this process never held it: another instance, a restart, or older than six hours), counts it (`apply_no_waiter_*` in the day's counters), and logs how every wait ended (a fixed sentence, no text). The next time it happens in production the counters say which. `cancelled` points at a proxy or the browser; `not_here` points at a second instance or a restart. `/api/health` now shows a pid and start time (item 3), so two pids at one address, or a start time that keeps moving, is visible from outside.
- **Item 3, single-process state: audited and made visible, not moved.** What actually depends on one process: the wait for Apply, the notes of what a proposal changed, and the usage counts that flush in batches (a restart loses up to a minute of them, which matters once money is involved). What does not: the graph checkpointer (MongoDB), a conversation's transcript (read back from the database) and steering (falls back to a normal follow-up). The rule is one worker. The server now logs a warning at start-up when the environment asks for more (`WEB_CONCURRENCY`, `UVICORN_WORKERS`, `GUNICORN_WORKERS`, `--workers`), which cannot see the host's own start command, so check Render's by hand. Moving the wait for Apply into the database is the fix if more than one instance is ever needed; not built, because nothing shows it is needed.
- **Item 6, cost plan: the message half done.** Where a limit stops someone (the blocked reply, and the blocked banner) it now says a paid option for people who want more is planned and not available yet (`budget_guard.PAID_OPTION_NOTE`; `PAID_OPTION_NOTICE=off` removes it; never in a crisis reply; no date, no price). The Help page says the same. Not done: tuning the per-person and daily numbers for a beta, which is an env decision for Jack (`LLM_USER_BUDGET_DAILY_USD`, `LLM_BUDGET_DAILY_USD`), and the paid tier itself (`docs/paid-tier-plan.md`, step 1 of 7 done).

- **Item 2, consent audit: first pass done** (`docs/consent-audit.md`). Fixed: the diff reviewer and the conversation-summary model no longer send a person's words to Claude unless they chose it; the Privacy page now names seven services it omitted and no longer says Claude is used "only in code work" (the setting is the tool model and runs every tool step, so it is now labelled "Tool model"). A test (`test_privacy_disclosure.py`) fails when a service or model client appears without being listed. OPEN: Render's `TOOL_AGENT_PROVIDER`.
- **Item 9, terms and data rights: drafted, not finished.** Terms sections 4 to 7 added (not a professional or emergency service, your files and computer, models and services, usage limits with a paid option only planned). A lawyer should read them. No self-service account deletion or full export exists (deletion is by email); a collection registry for both is proposed in `docs/consent-audit.md`.
- **Logo: swapped** (the new mark in the app, on the landing page and as the favicon; the old swirl files are unused).

- **Paid tier: nearly all that can be built without Stripe is built** (docs/paid-tier-plan.md Status): ledger, charge, guard hook, ceilings, processing line, refunds, dispute freeze, the Billing card. Decisions made: show the fee, $5 minimum, refund unused credit on request, deletion of an account by email is enough for now. Waiting on the Stripe account and an accountant/lawyer.
- **The runner:** an AI reviewer has cleared each runner PR as it was made; that is a useful first reader, not an independent one (it saw changes one at a time, not the whole command language). Fine for an opt-in beta; get a human second reader before opening it widely.

## Should be watched, not blocking
- Features built recently and not yet run on a real model or in production: the plan-end Sonnet review, the hybrid Plan/Execute flow, the second-reading reviewer, the combo changes, the presets' double save.
- Per-person limits are only as good as `LLM_PRICES`; Google's prices double on 2027-01-01.
- Nothing yet tells Jack when production is failing (counters exist; alerts do not). UNVERIFIED.

## If a beta first
Invite-only list; coding agent, runner and folder editing limited to people who ask for them; the paid-tier copy in the limit messages; the per-person cap kept low; one person (Jack) reads the counters daily for the first two weeks; items 1, 2, 3 and 6 done before the first invite.
